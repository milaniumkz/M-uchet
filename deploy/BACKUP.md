# Зашифрованная копия и восстановление

`deploy/backup.mjs` работает на хосте с Node24 и Docker Compose. Он делает согласованный снимок БД и всего `/app/data`: останавливает единственный API, выполняет PostgreSQL17 `pg_dump -Fc`, архивирует файлы и снова запускает API. На время снимка будет короткое окно обслуживания. Оператор должен исключить другие процессы записи, включая ручные серверные команды. Снимок не является online/PITR-репликацией.

Создайте отдельный бинарный ключ32байта вне репозитория, с правами0400/0600. Например, на будущем сервере:

```sh
umask 077
openssl rand -out /secure/muchet-backup.key 32
```

Храните запасную копию ключа отдельно от зашифрованных архивов. Потерянный ключ восстановить нельзя. Пароль, ключ и URL БД не передаются в аргументах команд; передаются только пути к защищённым файлам.

При наличии настроек Compose в защищённом `/secure/muchet.env`:

```sh
node --env-file=/secure/muchet.env deploy/backup.mjs create \
  --directory /backups/muchet --key-file /secure/muchet-backup.key
```

По умолчанию используется проект Compose `muchet`; иной проект задаётся `MUCHET_COMPOSE_PROJECT`. API должен быть запущен до начала. После ошибки источника API запускается снова, незавершённый комплект удаляется. При сбое самого повторного запуска оператор должен восстановить сервис; готовый комплект, если он уже опубликован, остаётся в каталоге копий.

Комплект содержит `database.dump.enc`, `data.tar.gz.enc`, `manifest.json`. База и файлы шифруются независимо AES-256-GCM с отдельными случайными nonce; заголовок аутентифицируется, тег проверяется при расшифровке. Манифест содержит дату, версию схемы, сведения об образе и SHA256 шифротекстов; в нём нет бухгалтерских записей и паролей. Рабочие файлы имеют права0600, временные каталоги —0700. Публикуется только завершённый каталог. Ключ не копируется в комплект. Результат следует переносить в отдельное хранилище и регулярно проверять восстановлением; автоматическое расписание и внешнее хранилище ещё не настроены.

## Восстановление в отдельный контур

Сначала расшифруйте в защищённый временный каталог:

```sh
node deploy/backup.mjs decrypt --backup /backups/muchet/CHOSEN_BUNDLE \
  --directory /secure/restore --key-file /secure/muchet-backup.key
```

Неверный ключ, повреждение шифротекста или ошибка второго файла удаляют временную расшифровку; готовый каталог не публикуется. Успешный вывод содержит путь `PLAIN_DIRECTORY` с `database.dump` и `data.tar.gz`. Эти файлы уже не зашифрованы: храните их закрытыми и удалите после приёмки.

Для восстановления используйте **новый проект и новые тома**, образ из копируемой версии и свободный loopback-порт. Не выполняйте `pg_restore` в рабочую БД. Команды ниже предполагают подготовленные переменные-пути секретов, `MUCHET_IMAGE` нужной версии и `MUCHET_PORT=18081`:

```sh
docker compose -f deploy/compose.yaml -p muchet-restore up -d --wait db
docker compose -f deploy/compose.yaml -p muchet-restore exec -T db \
  pg_restore -U muchet -d muchet --no-owner --no-acl < "$PLAIN_DIRECTORY/database.dump"
docker compose -f deploy/compose.yaml -p muchet-restore run --rm --no-deps -T \
  --entrypoint tar api -xzf - -C /app/data < "$PLAIN_DIRECTORY/data.tar.gz"
docker compose -f deploy/compose.yaml -p muchet-restore up -d --wait api
```

Проверьте вход, документы, точные остатки, задачи и приватные файлы в восстановленном контуре. Переключение рабочего домена выполняется отдельно после приёмки. Не удаляйте исходные тома ради проверки восстановления.

`make test-container` проверяет этот путь на отдельной синтетической БД: зашифрованный комплект → расшифровка → реальный pg_restore в новую БД и распаковка файла. Также проверяются неверный ключ, повреждение архива и возобновление API после неудачного pg_dump. Существующие данные development не используются. На сервере пользователя восстановление ещё не выполнялось.
