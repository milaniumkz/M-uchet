# ADR-001: текущий PostgreSQL-контур и границы миграции

Решение от 2026-10-20. Пользователь задал PostgreSQL, модульный монолит и сохранение Flutter UI. Ранний SQLite-прототип из b81c0f1 заменён PostgreSQL 17 и SQL-миграциями. Реальные пользовательские данные из SQLite не переносились: их нет; ранее созданный локальный SQLite-файл не удалялся.

Текущий API сохраняет Fastify/JavaScript вместо новой оболочки NestJS/TypeScript: это обоснованная адаптация уже написанного и проверенного кода, без микросервисов. Такая адаптация не означает завершённой типизации, слоёв всех требуемых модулей или полного контракта OpenAPI. Закреплены lockfile, Node 24 и digest PostgreSQL image.

Бизнес-команда выполняется в PostgreSQL-транзакции. До изменения остатка берётся SELECT FOR UPDATE строки организации; это простой консервативный способ сериализации её команд между экземплярами API. После блокировки повторно проверяются членство/права и идемпотентность. Ответ, аудит, регистры и проводки фиксируются одним commit. Цена простоты — последовательное выполнение всех команд одной организации; нагрузочный предел пока не измерялся.

Суммы API — integer minor units с проверками safe integer; в БД — NUMERIC(20,0). Строки проводок нормализованы в journal_lines, проверяется сумма дебета/кредита deferred trigger. Записи неизменяемы, сторно связано с оригиналом. Часовой пояс организации по умолчанию Asia/Almaty; business_date — отдельная DATE без преобразования в локальный Date. Утверждённый план счетов Казахстана и юридически значимые формулы отсутствуют до изучения первоисточников.

SQLite не остаётся запасным backend. Ошибка соединения с PostgreSQL не переключает систему на локальную БД или mock. Development seed выключен вне development. Настоящий production bootstrap, cookie/CSRF/refresh-контур, RLS/дополнительные роли БД, хранилище ключей и организационная история профиля остаются требованиями следующего этапа.

Flutter-экраны и их модели сохранены. Массовая текстовая замена импортов без тестирования запрещена как способ заявить готовность миграции. Новый адаптер должен поддержать loading/empty/errors/conflicts, а критические операции передать бизнес-командам, не воспроизводить прямой Firestore CRUD на финансовых регистрах. Статический screen-map — инвентарь, не доказательство работающей интеграции.

**Уточнение решения:** последнее указание владельца отменило запрет редактирования и блокировку закрытого периода. См. requirements/2026-10-20-editing.md. Первоначальные immutable triggers заменены историей версий и транзакционными редакторами; прежние описания запрета в этом ADR относятся к прошлому состоянию.
